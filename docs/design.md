# 设计说明与实验论证

## 1. 信号模型与角度约定

窄带远场平面波，阵列沿 x 轴布放，角度 θ 为来波与阵列**法线**（broadside）
的夹角。M 阵元 ULA 阵元位置（居中放置，居中与否不影响任何协方差类估计）：

```
x_m = (m − (M−1)/2)·d + Δx_m,   m = 0..M−1
```

导向矢量元素 `a_m(θ) = exp(j·2π/λ·x_m·sin θ)`。可选阵元位置误差 Δx_m。

## 2. 协方差

样本协方差采用 MLE 归一化 `C = X X^H / K`，归一化对 MUSIC 谱、特征值
准则与功率估计都没有影响，但能让 C 的对角元直接读作各通道总功率，
SNR 估计直观。每次更新后做 `C ← (C + C^H)/2` 强制精确厄米。

## 3. 增量更新：两种定义与一致性

### 3.1 定长滑动窗口（默认）

维护最近 W 条快拍的环形队列与未归一化和 `S = Σ x_k x_k^H`：

```
新批进入: 对每条 x：若窗口满，S −= x_old x_old^H，N −= 1；
                             S += x x^H，N += 1
C = S / N
```

旧数据在滚出窗口时被**干净地减去**，与“只对窗口内快拍一次性算
`XX^H/W`”逐项相同（浮点上相对误差 1e-12 量级，见
`tests/test_incremental.py`）。代价是要留窗口内全部快拍，内存 O(M²·W)
量级的向量存储（M≤64、W=256 约 0.3 MB）。

### 3.2 指数遗忘因子（按快拍加权，与切批方式无关）

权重**按快拍**定义，与调用方怎么分包无关：按提交顺序，最新一条快拍
权重为 1，往前每条乘 α。对 N 条已存快拍（x_N 最新）：

```
C = (Σ_{j=0..N-1} α^j · x_{N-j} x_{N-j}^H) / (Σ_j α^j)
n_eff = Σ_j α^j
```

设当前有效快拍数为 n_eff、未归一化加权和 S = n_eff·C，一次追加 K 条
X = [x_1,…,x_K]（x_K 最新）：

```
S  <- α^K · S + Σ_{i=1..K} α^(K-i) · x_i x_i^H
n_eff <- α^K · n_eff + Σ_{i=1..K} α^(K-i)
C  <- S / n_eff
```

批内权重由 `α ** [K-1,…,1,0]` 一次生成（NumPy 逐元素幂），旧状态整体
乘 `α^K`。整块推（K=N）、每包 16 条、逐条推（K=1）三种推法得到的
S、n_eff、C 严格是同一个量；增量结果与一次性
`forgetting_covariance(X, α)`（以及调用方在外部按同一 NumPy 定义直接
算的权重和）逐元素对齐，相对误差 1e-12 量级（题面要求 1e-9）。

连续单条追加时稳态有效快拍数 `n_eff -> 1/(1−α)`；取
`α = (W−1)/(W+1)` 使两方式等效记忆同为 W，公平比较。无需保留历史
快拍（内存 O(M²)）。最新一条权重恒为 1，故分母 n_eff ≥ 1；α 很小、
K 很大（如 α=0.5、单批 10000 条）时旧权重按浮点下溢为 0——与一次性
NumPy 参考实现 `α ** arange` 行为一致，不会 NaN 或除零。

> **历史缺陷（v1）**：升级前的递推是
> `C <- (α n_eff C + X X^H) / (α n_eff + K)`、`n_eff <- α n_eff + K`，
> 把一整批 K 条**等权**处理、只在批与批之间乘一次 α。于是同一份快拍
> 整块推、每包 16 条推、逐条推会得到不同的协方差和有效快拍数（实测
> 600 条 α=0.98 时角度分别报 −18.97° / +19.63° / +19.99°，n_eff 为
> 600 / 420.7 / 50.0）。α=1 时乘不乘 α 都一样，所以缺陷长期被掩盖。
> 该旧口径标识为 `forgetting_batch_v1_legacy`，不再接受追加，见第 12 节。

### 3.3 sliding 与 forgetting 的取舍

两者的本质差别是**旧数据的权重消退形状**：

* sliding：旧数据权重是平顶矩形——在窗内权重 1，滚出窗口瞬间为 0；
* forgetting：旧数据权重按 α^t 几何衰减——永不真正为 0。有效记忆
  `1/(1−α)` 条；等效记忆同为 W 时，几何衰减比矩形窗“平均年龄”更年轻，
  阶跃后权重重心移动得更快（实测跟拍延迟反而短于 sliding，见第 4 节），
  代价是阶跃前的降噪窗口略浅、稳态方差略大。

## 4. 跟踪实验（角度阶跃：−20° → +20°）

复现：`python -m experiments.tracking_experiment`
（固定 5 个种子 101/202/303/404/505，M=8、d=λ/2、SNR=15 dB、每 16 条
快拍出一次 D=1 MUSIC 估计）。

* **跟拍延迟**：阶跃后估计连续 3 次落入新角 ±1° 时距阶跃点的快拍数；
* **稳态 RMSE**：阶跃后 6W–12W 区间相对 +20° 的均方根误差；
* 两个场景：`warm` 阶跃前仅 2W 条历史；`settled` 阶跃前已有 10W 条
  （常驻后端长时间运行的典型情形）。

### 实测结果（修复后，按快拍加权口径）

| 场景 | 方式 | 等效记忆 | 跟拍延迟 P90/最大（快拍） | 延迟/W | 暂态RMSE 0–3W | 稳态RMSE 阶跃后 |
|---|---|---|---|---|---|---|
| warm | 滑动 W=128 | 128 | 80 / 80 | 0.63 | 16.70° | 0.0407° |
| warm | 遗忘 α=.9845 | 128 | 57 / 64 | 0.45 | 14.21° | 0.0402° |
| warm | 滑动 W=256 | 256 | 144 / 144 | 0.56 | 16.28° | 0.0238° |
| warm | 遗忘 α=.9922 | 256 | 96 / 96 | 0.38 | 13.41° | 0.0237° |
| warm | 滑动 W=512 | 512 | 272 / 272 | 0.53 | 16.16° | 0.0155° |
| warm | 遗忘 α=.9961 | 512 | 192 / 192 | 0.38 | 13.39° | 0.0159° |
| **settled** | **滑动 W=256** | 256 | **144 / 144** | **0.56** | 16.67° | **0.0238°** |
| settled | 遗忘 α=.9922 | 256 | 96 / 96 | 0.38 | 13.68° | 0.0237° |
| settled | 滑动 W=128 | 128 | 80 / 80 | 0.63 | 17.05° | 0.0407° |
| settled | 遗忘 α=.9845 | 128 | 64 / 64 | 0.50 | 14.14° | 0.0402° |
| settled | 滑动 W=512 | 512 | 272 / 272 | 0.53 | 16.47° | 0.0155° |
| settled | 遗忘 α=.9961 | 512 | 192 / 192 | 0.38 | 13.52° | 0.0159° |

（完整数据含最大值、阶跃前 RMSE：`experiments/results/tracking_results.json`）

### 结论

1. **sliding 的跟拍延迟约 0.53–0.63W，且与阶跃前历史长度完全无关**。
   W=256 默认下：阶跃后约 **144 条快拍**（每 16 条估一次即约 9 次估计）
   持续进入新角 ±1°，稳态 RMSE 约 **0.024°**（M=8、SNR=15 dB）。
2. 修复后的 forgetting 按快拍几何衰减，等效记忆 W 下权重平均年龄更年轻，
   跟拍延迟 **0.38–0.50W（W=256 约 96 条）反而短于 sliding**，且与
   阶跃前历史长度无关（warm 与 settled 几乎相同）——几何权重永远只看
   最近约 1/(1−α) 条，不存在“积累越久拖得越长”的现象。
3. 两者稳态 RMSE 在等效记忆下几乎相同（W=256 都是 0.024°；W=512
   forgetting 0.0159° vs sliding 0.0155°）；forgetting 省内存（O(M²)
   vs O(M·W)），sliding 的平顶权重对窗内数据降噪更直观、且“记忆截断”
   语义更容易解释。
4. 内存代价（W=256、M=8 约 32 KB；M=64 约 2.1 MB）在本规模下可忽略。

故默认仍取 `sliding / W=256`（截断语义清晰、窗内等权）；需要更短的
阶跃响应时间或内存极紧张时选 forgetting，按可接受的等效记忆 W 取
`α = (W−1)/(W+1)`。

> 注：本文档早期版本的 forgetting 实验数字（延迟 1.7W、settled 4.6W）
> 是用 v1 旧递推（批内等权）跑出的——实验脚本每次推 16 条，旧递推把
> α 乘在“16 条大包”上，实际等效记忆约为名义值的 16 倍，数字已随修复
> 全部重跑更新。

## 5. 源数判定（MDL / AIC）

对样本协方差降序特征值 λ_i，候选信源数 k 的噪声子空间为
{λ_k,…,λ_{M−1}}，记其算术均值与几何均值之比：

```
L(k) = (M−k)·ln( AM(λ_{k:}) / GM(λ_{k:}) )
AIC(k) = 2 N L(k) + 2 k(2M−k)
MDL(k) =   N L(k) + ½ k(2M−k) ln N
```

取使准则最小的 k。FB 平滑时 N 使用等效快拍数（原始 K 乘 2(M−L+1)）。
高 SNR、K 足够时 MDL 一致地给出真实源数（测试：3 源、20 dB、800 条）。
调用方也可以直接指定整数源数；源数 ≥（子阵）阵元数会被拒绝。

## 6. 前后向空间平滑

子阵长度 L 可配（默认 ⌈2M/3⌉），共 M−L+1 个前向子阵与同数个后向子阵
（后向 `J C_f^H J`，J 为交换阵），平均后秩恢复为 min(D, L)，可分辨的
最多非相干信源数为 L−1；相干源用平滑恢复秩。开启平滑后 MUSIC 在 L 维
子阵几何上完成，CRB 的阵元数、孔径随之按子阵计算，等效快拍数乘
2(M−L+1)。指定源数达到 L 会得到明确错误（要求增大子阵长度）。

## 7. MUSIC 扫描与细化

粗扫网格 `θ_min + i·step`（缺省 −90°…90°、0.5°，点数上限 20 万），
谱 `P(θ) = 1 / (a^H E_n E_n^H a)`；取严格局部极大的最强 D 个峰，每峰
在相邻网格构成的 ±step 区间内做 50 次黄金分割一维搜索（区间收缩
0.618^50 ≈ 5e−11 倍步长），精度比步长细十个数量级，远超“细一个数量级”
的要求。测试中真值偏离粗网格（18.37°、步长 0.5°）时误差仍 <0.05°。

## 8. CRB

单信源、空间白高斯噪声、确定性（条件）模型，对方位角（弧度）：

```
CRB(θ) = 1 / [2 N · SNR · (D^H P_a^⊥ D)]
D = da/dθ = j k x cosθ · a
```

多源结果中逐源给出：由特征分解取噪声功率 σ²、向量化协方差最小二乘
拟合各源功率 P_i，SNR_i = P_i/σ²；CRB 标准差（度）随每条估计返回，
带真值时再给 `|θ̂−θ| / CRB_std`。SNR 0→20 dB、每点 40 次重复的实测：
RMSE 随 SNR 严格下降，高 SNR 段（15/20 dB）该比值约 0.9–1.2，<3。
开启平滑时按子阵几何与等效快拍数计算（平滑处理增益未额外计入，估计偏
保守）。

## 9. 栅瓣模糊

理想 ULA 的导向相位只含 `(d/λ) sin θ`。当 d > λ/2 时存在可见别名：

```
sin θ′ = sin θ ± n·λ/d,   |sin θ′| < 1
```

服务对每个估计角枚举全部可见别名（n=1,2,…）随结果返回
（`grating_pairs`），并置 `grating_ambiguous: true`；d=λ、θ=10° 时
别名 θ′≈−56.6°。带位置误差的阵列无严格栅瓣，不报此标志。

## 10. 合成的逐位复现

只使用 `numpy.random.default_rng(seed)`，绘制顺序固定（先 M×K 噪声，
再信源包络；相干组先抽公共包络再抽各源固定相位），所有缩放系数确定。
同 (参数, seed) 的返回数组 `np.array_equal` 逐位相同（测试同时与
HTTP 响应交叉验证）。相干源共享一个 CN(0,1) 包络并乘种子决定的固定
相位，秩严格为 1。

## 11. 并发与持久化

* 每个会话一把可重入锁；FastAPI 的同步路由跑在线程池，同会话并发追加
  被串行化，最终状态等价于某一先后顺序的串行追加（测试直接比对落盘
  窗口内容等于 AB 或 BA 之一，且 C 与窗口自洽）；
* `batch_id` 去重集合与 C/窗口在同一个 `state.npz` 中，经临时文件 +
  `os.replace` 原子落盘；同号批次重复提交不重计；
* 结果写 `results.jsonl`（append + fsync），版本号由既有记录数 +1
  得到，重启后连续；
* SSE 推送用订阅时捕获的事件循环 `call_soon_threadsafe` 跨线程投递，
  慢消费者丢旧保新；
* 启动时扫描数据目录恢复全部会话（协方差状态懒加载）。

## 12. 遗忘因子口径升级与老会话迁移

### 12.1 口径标识

每个会话在配置和状态接口里都带**累积口径标识** `rule`，两种现存口径：

| rule | method | 权重定义 | 可否追加 |
|---|---|---|---|
| `sliding_window_v1` | sliding | 窗口内等权（语义从未变过） | 是 |
| `forgetting_snapshot_v2` | forgetting | 最新一条权重 1、往前每条乘 α（当前口径） | 是 |
| `forgetting_batch_v1_legacy` | forgetting | 旧口径：批内等权、仅批间乘 α（分包相关） | **否，冻结只读** |

`GET /sessions`、`GET /sessions/{id}` 返回 `accumulation_rule` 与
`append_frozen`；`config.json` 的 `update.rule` 落同样的值，state.npz
里也写 `rule`。调用方不会在不知情的情况下把两种口径拼到同一条时间线上。

### 12.2 老会话（数据目录长期挂载）的处理：冻结为只读

升级重启时，`config.json` 里 `version < 2` 且 `method=forgetting` 的会话
被识别为旧口径会话，标成 `forgetting_batch_v1_legacy` 并**冻结**：

* 会话照常列出、状态照常查询、历史结果按版本号**逐字**读出（results.jsonl
  不重写，state.npz 不重写——升级只原子重写 config.json 补上 rule 标记与
  版本号，测试对旧文件做 SHA-256 逐字节校验）；
* 仍可用冻结前的状态出估计（只读，结果按新版本号追加），轮询与 SSE 补发
  路径行为不变；
* **追加快拍返回 `409 session_frozen`**（在批次去重之前判定，旧批次号
  重放也不改变状态），错误消息说明原因并建议另开会话；
* 旧 sliding 会话不受任何影响，rule 补成 `sliding_window_v1`，继续追加。

需要继续采集的同学新建 forgetting 会话即可，新会话从第一条起就是
v2 口径。

### 12.3 候选方案与放弃理由

**方案 A（已采纳）：旧遗忘会话冻结只读，新数据另开会话。**
语义最干净：没有任何一个会话的协方差是两种权重定义的混合，旧结果的
可重复性得到保证；实现上不需要在热路径里永久维护两套递推。代价仅是
继续采集要换 session_id（一个 POST 的成本），且无法再向旧 id 追加——
这正是题面“不能悄悄把两种口径拼在一起”的要求。

**方案 B：沿用旧算法继续追加（按批次等权）。** 放弃，原因：(1) 旧算法
本身是错的——结果依赖分包方式，整块/16 条包/逐条三种推法能给出 −18.97°
/+19.63°/+19.99° 三个方向，继续沿用等于保留缺陷；(2) 要永久在代码里
保留两套遗忘递推和两套一次性参考实现，且每次新增数据都强化一条分包相关
的时间线；(3) 新老会话行为分叉会长期存在，调用方更难理解。

**方案 C：从某个分界点起无缝切到新算法（旧段按旧权重、新段按新权重，
拼成一个协方差）。** 放弃，原因：(1) 拼出来的协方差不对应任何单一定义，
既不等于按旧定义一次性算、也不等于按新定义一次性算，违反“同一个定义下
增量与批处理一致”的核心验收；(2) 旧口径下服务从未保存过原始快拍，磁盘
上只有一个聚合矩阵 C，无法给旧段重新赋予按快拍的权重——分界点之前的
权重结构在信息论上已经丢失，无法忠实重建；(3) 即便硬拼，旧段的 n_eff
记账口径（按批计）与新段（按条计）不同，源数判定和 CRB 的分母会混口径。

**方案 D：用磁盘上的聚合 C 反推/重采样出旧快拍再按 v2 重放。** 放弃：
8×8 协方差（64 个复数）无法反解出几百上千条原始快拍，任何“造一批快拍
使其协方差等于 C”的重构都改变了时间顺序与逐快拍权重，是伪重建，结果
不可追溯也无法与外部 NumPy 参考对齐。

方案 A 是唯一同时满足“历史逐字可查”“不混口径”“新结果定义正确”的选择。

### 12.4 升级前后的存储兼容

* 读取端兼容无 `rule` 键的旧 state.npz：sliding 按 sliding 处理；
  forgetting 无 rule 即视为 legacy（与 config 标记双保险）；
* 新写入的 state.npz 总是带 `rule`；配置版本号升到 2；
* 旧 `LegacyForgettingAccumulator` 只保留“恢复 + 只读估计”所需逻辑，
  `add_batch` 直接抛 `CovarianceError`（会话层先以 `SessionFrozenError`
  拦截并回 409），冻结状态永远不会被新递推改写。
